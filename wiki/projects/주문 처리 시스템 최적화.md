# 주문 처리 시스템 최적화

현재 진행 중인 업무 프로젝트다. 주문 처리 시스템의 병목을 찾고, 성능과 안정성을 측정 가능한 방식으로 개선하는 것을 목표로 한다.

## Scope

- 주문 처리 흐름의 주요 병목 식별
- 데이터베이스, 캐시, 메시징, 애플리케이션 레벨 개선 검토
- 개선 전후 지표 비교
- 장애 가능성과 운영 복잡도 평가

## Kafka 적용 체크포인트

- 주문 이벤트 key를 주문 ID로 둘지, 사용자 ID나 다른 도메인 key로 둘지 결정한다.
- consumer가 at-least-once 중복 처리를 견딜 수 있도록 멱등성을 확인한다.
- Kafka 내부 read-process-write 흐름인지, 외부 DB 쓰기가 포함되는지 구분해 exactly-once 필요성을 판단한다.
- 운영 cluster가 KRaft mode인지 ZooKeeper mode인지 명시하고, metric과 배포 설정을 맞춘다.
- changelog 성격의 topic에는 log compaction 적용 가능성을 검토한다.
